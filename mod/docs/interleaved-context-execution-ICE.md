# 交错式上下文执行

**Interleaved Context Execution(ICE)——重排缓冲、顺序退休,与单写者上下文中的并发认知**

> 作者:Vonish
> 状态:构想稿 v0.1 · 2026-07-17
> 姊妹理论:《认知事件溯源原则》(CESP / CIAP)

> 核心契约:
> **Parallelism lives in the executor. Serialization lives in the context.**
> **Immutability begins at retirement.**
>
> 并行在执行器,串行在上下文;不朽,自退休始。

---

## 摘要

现行 LLM 函数调用是同步的:每次工具调用阻塞推理,直到结果返回。对于运行在实时环境中的 Agent(游戏 NPC、浏览器操作体、机器人),这意味着三重浪费:墙钟时间空转、外部事件被迫排队、以及对突发中断只能"打断重来"。本文提出**交错式上下文执行(ICE)**:在不改动模型、不接触解码循环、只依赖标准请求-响应 API 的前提下,由编排层实现异步工具派发与并发认知——工具调用立即以占位符落账,模型在结果返回前继续处理独立工作流;结果乱序返回后,在上下文**尾部的重排缓冲区**内完成有限编排,随后按因果序**顺序退休**为不可变历史。ICE 与姊妹理论 CIAP 的关系不是修正而是补全:CIAP 管辖已退休的疆域,ICE 定义退休之前的境外规则,不可变性获得了它的生效时刻。

## 1. 动机:同步阻塞的三重浪费

考察一个具体场景。Minecraft NPC 正在执行区域扫描(一个耗时数秒的工具调用),此刻被僵尸击中。同步模型给出的选项都很难看:

- **等**:扫描返回前不能思考,僵尸白打;
- **打断**:中止扫描、丢弃半途的推理,处理僵尸后重来——已生成的 token 与已执行的半程全部作废;
- **分叉**:开第二条上下文处理僵尸,事后合并——合并点之后的序列是全新前缀,缓存核爆。

而 Agent 真正需要的行为是显然的:**扫描继续跑,思考不打断,反击立即开始,事后三线穿插成一条连贯的历史。**这正是异步编程对主程序流的承诺,也是本文要在"上下文即一条线性 token 带"的物理约束下兑现的承诺。

同步阻塞的浪费可归纳为三重:

1. **墙钟浪费**:工具执行期间推理算力闲置,任务总时长 = Σ(推理 + 工具)串行和;
2. **响应浪费**:外部事件必须等待当前"推理-工具"回合完整结束才能进入上下文;
3. **中断浪费**:紧急事件若强行插入,唯一手段是废弃在途生成,已付 token 沉没。

## 2. 约束地形:本理论在什么地面上盖房

ICE 不是空中设计,它的每条规则都由四块既存地形挤压成型。

### 2.1 前缀缓存经济学(首变异点定律)

现代 API 的 prompt cache 按最长公共前缀命中。**决定缓存效率的不是变异内容有多长,而是首个变异字节出现得有多早**:上下文中段改动一行,其后全部序列作废重算;尾部追加则整段历史以缓存读价格(约为常规输入的十分之一)复用。因此任何并发机制若以"回头改写中段"为代价,收益会被缓存损失整体吞没。

### 2.2 CIAP 管辖权

姊妹理论 CIAP 规定:认知以不可变事件追加,历史不可无痕改写,重写仅发生于 compaction 边界。ICE 必须与之相容——本文 §7 将说明,相容的方式不是给 CIAP 开例外,而是精确划定它的生效时刻。

### 2.3 签名不可变

带扩展思考的 thinking 块由平台签名,回传时必须与原始响应**逐字节一致**,任何改动即拒。推论:**任何形式的上下文编排,都不得触碰签名块**。这条约束将在 §4.7 反向决定 ICE 的一个前置条件。

### 2.4 厂商主权边界

请求-响应 API 对上下文的管辖精确到两件事:**结构**(每个 tool_use 必须在紧随的 user 消息中有 id 配对的 tool_result)与**签名**(见上)。除此之外,tool_result 的**内容**是编排层的主权领土——写真实结果、写占位符、写指导语,平台一概不核验。ICE 的全部操作空间,就是这两条管辖线之外的自由。

## 3. 相关工作与三个失败方案

### 3.1 AsyncLM:解码环内的中断

AsyncLM(arXiv:2412.07017)在推理管线层实现了同一目标:函数调用非阻塞,函数返回时由执行器向 LLM **正在生成的 token 流中注入中断 token**,以 CML 记号([CALL] / [INTR] / [TRAP])组织异步调用与依赖等待,配合微调使模型理解中断语义,端到端延迟降低 1.6–5.4 倍。

AsyncLM 证明了交错执行的收益真实存在,也解释了为何商业 API 无法提供它:**该方案要求拥有解码循环**——微调模型 + 改造推理管线。API 厂商出售的是请求-响应合同,生成一旦开始,外界无法注入任何内容。ICE 的定位由此确定:**在编排层、于存量 API 之上,复现 AsyncLM 的异步语义**——不微调、不触碰解码、可移植于任何 messages 风格接口。代价是交错粒度从 token 级降为轮次级;§6 将论证该粒度对 Agent 工作负载已经足够。

### 3.2 CPU 乱序执行:重排缓冲区与顺序退休

乱序处理器允许指令乱序**执行**,但强制按程序序**退休**(in-order retirement):指令在重排缓冲区(reorder buffer)内自由完成,退休一刻起结果不可变、对外可见。这套四十年工龄的机制解决的正是 ICE 的核心矛盾——**执行要乱序,历史要有序**。ICE 将其整体移植:上下文尾部即重排缓冲区,缓存断点即退休边界。

### 3.3 三个失败方案

| 方案 | 失败方式 |
|---|---|
| 同步阻塞 | 三重浪费(§1) |
| 分叉-合并 | 合并点后全新前缀,缓存核爆;且两条分支互不知情,合并语义困难 |
| 中段替换 | 占位符落账后,并行事件已追加其后;工具完成时占位符位于**中段**,替换打爆其后全部缓存——交错越成功,替换点越深,损失越大。且缝合 thinking 违反签名纪律(§2.3) |

中段替换值得单独批注:它是本理论的前身直觉,其失败不在方向而在时机与疆界——修正它,即得 ICE。

## 4. 模型定义

### 4.1 上下文二分

```text
──── 已退休区(CIAP 全效)────────────┃ 水位线 ┃──── 重排缓冲区 ────
  不可变 · 已缓存 · 一个字节不许碰      ▲            占位符 · 并行事件 ·
  ...历史事件流...              cache 断点钉此    乱序返回的结果 · 可编排
```

- **已退休区**:不可变历史。缓存断点(cache breakpoint)钉在水位线上,该区享受全额缓存命中。
- **重排缓冲区**:上下文最尾部的一小段,编排层的工作台。区内字节允许重排、合并、改写——每次改写重付该段 token 费用,但因其位于尾部,**不波及前方任何缓存**。
- **水位线**:两区分界。定义见 §4.4。

### 4.2 占位符协议

工具派发后,编排层**立即**构造 tool_result 归还——满足 API 的结构配对要求——内容为占位符:

```xml
<tool_result tool_use_id="toolu_017" >
  <status>executing</status>
  <task id="7" kind="scan_blocks" dispatched_at="184220"/>
  <guidance>结果尚未返回。请勿臆测结果内容;
  可继续处理与该结果无依赖的工作,或声明等待。</guidance>
</tool_result>
```

占位符的三要素:**taskId**(后续关联的锚)、**状态**(executing)、**指导语**(一两句话向模型解释语义,并明令禁止臆测)。指导语是占位符协议的灵魂——它把"结果未知"从一个异常状态变成模型可推理的一等公民。

### 4.3 双轨完成

工具结果返回时,按**预期时长**分流:

**短轨(缓冲区编排)**:预期秒级返回的任务。结果返回时占位符仍在缓冲区内 → 编排层将结果**原位合并**进占位符位置,并把期间落入的并行事件整理为因果序,整段等待退休。最终历史读起来如同一次干净的同步调用——但墙钟上它从未阻塞过。

**长轨(引用追加)**:预期分钟级以上的任务。占位符**立即退休**,内容定格为"已派发,勿等";完成时以引用事件追加于当前尾部:

```xml
<event seq="309" type="TASK_COMPLETED" ref="7">
  scan_blocks(task 7) 完成,结果:……
</event>
```

缝合由 taskId 的**逻辑关联**完成,不做字节手术。

双轨不是竞争方案,是按时长分流的搭档:短任务买"历史整洁",长任务买"水位线自由"(见下)。

### 4.4 退休规则

三条,缺一即溃:

1. **水位线 = 最老一个未解决依赖的位置。**缓冲区内所有事件的依赖(等待中的 taskId)构成集合;水位线钉在其中最早落账者之前。
2. **水位线单调前移,永不后退。**
3. **依赖全部解决的事件,按因果序越过水位线退休;退休即不朽,即入缓存,即归 CIAP 管辖。**

推论:一个占位符若走短轨,其退休被推迟到结果归位;若该任务实际很慢,它会**钉死水位线**,缓冲区随时间膨胀,"便宜的尾部"逐渐变贵——这正是长轨存在的理由:预期慢的任务让占位符立即退休,水位线不受其质押。

### 4.5 因果红线

缓冲区编排的唯一硬禁令:

> **结果不得跨越任何消费了其 pending 状态的决策点。**

若模型在占位符时代做出过依赖"结果未知"这一事实的决策(例如"扫描没回来,我先去杀僵尸"),则该结果**禁止**被编排到此决策之前——否则历史将显示模型未卜先知,后续读史(以及基于历史的自我认知、行为归因、CESP 的置信标记)全部被污染。触碰红线时的处置:放弃合并,强制转长轨(引用追加)。

历史可以整洁,不可以撒谎。整洁是编排的目标,诚实是编排的边界。

### 4.6 任务标签与活跃清单

- 事件信封(CESP 定义)新增 `taskId` 字段;并行流的每个事件携带所属任务标签。
- 活跃任务超过一条时,编排层以 `system_notice` 在尾部维护清单:"当前活跃:task 7(挖矿扫描,执行中)、task 12(战斗,进行中)"。清单本身遵循 CESP 纠偏协议(追加、带序号、最高序为准)。

### 4.7 前置条件:提炼层必须生效

§2.3 的签名纪律在此收网:缓冲区若含有签名 thinking 块,任何重排即拒。因此 **ICE 要求 CESP §7 的"提炼层"模式默认开启**——历史 thinking 不回传,重要推断以 INFERENCE 事件显式落账;缓冲区内只存在 text、tool_use/tool_result 与自定义事件,全部为可编排的自由字节。

交错执行与推断落账由此互为前提:不是两个独立特性,是一对咬合的齿轮。

## 5. 并发的真实住所:执行器与反射层

### 5.1 单写者约束(非正式定理)

线性 token 序列在结构上只容得下一个写者。两个生成过程同时延长同一条上下文,要么串行化(退化为轮次交错,即 ICE),要么分叉(合并即缓存核爆,且两分支互为盲区)。因此:**真正的并行永远不发生在上下文里;上下文的职责是并发活动的串行化记录。**并行的住所在下面两层。

### 5.2 执行器层

工具在编排层的进程池 / 异步运行时中真并发。上下文只记录派发与完成两个事件——这是 CESP"观测即提交"在执行域的直接应用:**执行本身也是被观测的世界过程,派发一个事件,完成一个事件**。

### 5.3 脊髓反射层

毫秒级反应(格挡、闪避、自动反击)不配走大脑。由脚本或极小模型构成反射层就地处理,主认知仅收到一条追加的感知事件:

```text
<event type="PERCEPTION" provenance="observed">
  遭僵尸袭击;反射层已反击,损失 2❤,威胁解除。
</event>
```

生物学同构:缩手反射发生在脊髓,信号不经皮层。反射层同时是 ICE 的减压阀——大量"中断"在到达上下文之前已被消化,真正需要认知参与的事件才进入缓冲区。

### 5.4 抢占策略

- **唯一允许被杀的是在途生成,永远不是上下文。**废弃一次生成损失的只是该次输出 token;上下文分毫无伤。
- 显式优先级表决定中断处置:威胁生命(半血遭袭)→ 中止在途生成、注入事件、重发;常规事件(玩家闲聊、扫描返回)→ 等待本轮自然结束(轮次时长通常为秒级,排队成本可忽略)。
- 优先级表必须显式配置,否则编排层将在"每次都打断"与"永不打断"之间摆烂。

### 5.5 依赖失速:停召,而非空转

下一步认知必须消费未返回的结果、且无其他独立工作可做时:**编排层停止发起新调用**,让上下文静止等待事件,而不是反复调用 API 询问"好了吗"。这是 AsyncLM 之 [TRAP] 在编排层的对应物——区别仅在暂停发生于调用间隙而非解码中途。模型侧的配合语义:允许其显式声明"等待 task 7",编排层据此进入停召。

## 6. 成本分析

### 6.1 缓存账

设已退休区 R、缓冲区 B(|B| ≪ |R|,受体积上限约束)。每轮成本:

```text
ICE:      |R| × 缓存读价 + |B| × 常规价 (+ 缓冲区改写时 B 的重付)
同步阻塞:  同上,但墙钟串行,且无并发收益
中段替换:  替换点后 ~|R|/2 量级 × 常规价(缓存报废)
分叉合并:  合并点后全部 × 常规价
```

ICE 将变异严格圈禁于尾部,前缀命中率与纯追加方案(CESP 基线)**渐近相同**;相对代价仅为缓冲区的翻新费,上界由 |B| 的体积上限控制。

### 6.2 缓冲区体积上限

缓冲区超限(token 数或事件数)即**强制退休**一批已解决依赖的事件——与 compaction 触发条件同构,粒度缩小为滚动进行。上限同时是慢任务钉死水位线的第二道保险(第一道是长轨分流)。

### 6.3 交错粒度的充分性论证

ICE 的交错粒度为轮次级(AsyncLM 为 token 级)。Agent 工作负载中,工具执行时长(秒—分钟)通常远大于单轮生成时长(秒),因此轮次级交错已能回收绝大部分墙钟浪费;token 级的额外收益主要存在于超短工具 + 超长生成的组合,该组合在实践中稀少。粒度损失换来的是:零微调、零推理管线改造、全 API 可移植。

## 7. 与 CIAP 的关系:不朽自退休始

表面上,ICE 允许改写(缓冲区内),与 CIAP"历史不可覆盖"相抵。实际上二者的和解在于回到 CIAP 的推导源头:该原则由缓存经济学与认知诚实**推导**而来,其管辖对象自始就是"已进入缓存、已成为历史"的序列。ICE 所做的,是给这条推导补上它一直缺少的一个定义:

> **不可变性自退休起生效。**退休之前,事件尚在成为历史的途中;退休之后,CIAP 全效,一个字节不许碰。

缓冲区不是 CIAP 的例外,而是它的**境外**——正如 Git 的暂存区不受"commit 不可改写"约束,提交之后才受。因果红线(§4.5)则保证境外行为不会伪造境内历史:即便在缓冲区内,编排也只许整理时序,不许倒置因果。

两理论的完整分工:

```text
CESP / CIAP   回答:什么可以成为历史,历史如何不被伪造。
ICE           回答:历史在凝固之前,如何容纳并发。
compaction    回答:凝固的历史,何时允许一次合法的重铸。
```

## 8. 开放问题

1. **依赖判定的自动化。**"该决策是否消费了 pending 状态"目前依赖保守规则(占位符与结果之间存在任何决策即禁止合并)。更细的判定需要模型自我声明(显式"等待 task N")或编排层的轻量语义分析;误判方向必须偏向保守(错杀合并 → 退化为长轨,无害;漏杀 → 伪造因果,有害)。
2. **多依赖拓扑。**多个 pending 交叉依赖时的水位线定义与退休序,需从"最老未解决依赖"推广为依赖 DAG 上的拓扑退休。
3. **编排序对模型的可读性。**短轨合并后的"整洁历史"与长轨的"引用穿插史",何者更利于模型后续推理,直觉不可靠,需 A/B 实证。
4. **缓冲区上限的整定。**|B| 过小则频繁强制退休、丧失编排空间;过大则翻新费与水位线风险上升。需按任务画像调参。
5. **与保真层的部分共存。**是否存在"缓冲区外保留签名 thinking、缓冲区内禁入"的混合模式,使 ICE 与 CESP 保真层不完全互斥。

## 9. 验收条件

```text
 1. 派发即占位:工具派发当轮,tool_result 以占位符归还,结构配对通过 API 校验
 2. 并发不阻塞:占位符存在期间,模型可完成 ≥1 个独立任务的完整"思考-行动"回合
 3. 短轨整洁史:秒级任务合并后,最终历史与同步执行的序列语义等价
 4. 长轨引用史:分钟级任务的占位符立即退休;完成事件以 ref 正确关联
 5. 因果红线:构造"决策消费 pending"用例,验证合并被强制转长轨(自动化审计)
 6. 水位线单调:任意事件序列下,水位线位置单调不减
 7. 缓存回归:连续 50 轮,水位线之前的 prefixHash 恒定不变
 8. 缓冲区受限:注入慢任务,验证体积上限触发强制退休,|B| 不越界
 9. 抢占无伤:中止在途生成后,上下文与已退休区逐字节不变
10. 反射减压:毫秒级威胁由反射层处理,主上下文仅收到单条感知事件
11. 停召生效:无独立工作 + 依赖未决时,API 调用频次归零直至事件到达
12. 端到端收益:含 ≥3 次秒级工具的任务上,墙钟时长对同步基线显著下降
    (参照 AsyncLM 的 1.6×–5.4× 区间设定目标)
```

第 7 条是全部承诺的最终兑现形式:**这套理论说了多少话,最后都由那串不变的哈希来验收。**

---

## 10. 结语

ICE 的每一个部件都不新:异步派发来自并发编程,重排缓冲与顺序退休来自处理器微架构,中断语义来自 AsyncLM,事件信封来自 CESP。新的只有一件事——证明这些部件可以在"一条线性 token 带 + 请求-响应合同 + 前缀缓存计费"的三重约束下装配成整机,且装配的代价被严格圈禁在上下文的最后几行里。

Agent 由此获得的能力,用最初的那个场景收束:扫描在跑,思考未断,僵尸已被反击,而这三件事最终躺在同一条按因果排好的、90% 已缓存的、逐字节诚实的历史里。
