# 肌肉库 — Motor Skills v1(草案,待主人验收)

**把 LLM 从土木工程里解放出来**

> 核心契约:
> **We do not ask the model to be a civil engineer with one-shot tools.**
> **复杂的物理协同动作是一块肌肉:一次调用,内部闭环,确定性完成。**
>
> 口号:大脑下单,肌肉施工。

---

## 0. 为什么需要肌肉库(实战病理)

2026-07-17 井底事故:Fenn 被寻路送进熔炉正下方 11 格的洞底,110 条消息
(约 1M prompt tokens)用 move_to / break_block / place_block 的单发工具
试图垫方块上爬——place_block 因"站在目标格里"永远找不到支撑面视线,
break_block 够不着,move_to 的仰角目标撞搜索预算。**每个单发工具都正确,
组合起来就是不可能完成的任务。**同夜三次 place_block 连续失败触发止损通知,
NPC 仍无法自行脱困。

结论:跳跃+垫脚、搭桥、脱困这类多 tick 物理协同,必须做成代码内闭环的肌肉,
暴露为一个工具调用。执行器里其实已有 PILLAR/BRIDGE 运动原语(Baritone 移植),
缺的是把它们打包成大脑可直接下单的肌肉。

## 1. v1 清单

| 肌肉 | 签名(草案) | 内部闭环 | 状态 |
|---|---|---|---|
| escape_to_surface | () | 垂直竖井:挖头顶+垫脚交替直上到 heightmap 地表;有镐+脚手架必成 | 井底事故的直接解药,未派工 |
| pillar_up | (height) | 原地垫脚 N 格(执行器 PILLAR 原语已在,包装+验收) | 未派工 |
| bridge_to | (x,y,z) | 平桥/斜桥到目标(BRIDGE 原语已在) | 未派工 |
| fight | (target, style) | 交战循环:满蓄力挥击、走位、评估器实时裁决打/撤 | 依赖交战评估引擎(施工中) |
| backtrack | (steps?) | 沿自己的航迹面包屑原路返回 | 依赖航迹环形缓冲(未派工) |

## 2. 设计红线

1. **确定性**:肌肉内部零 LLM、零随机;失败时返回精确原因与已完成进度
   (井底事故教训:模糊的失败消息比失败本身更贵)。
2. **可中断**:脊髓反射可随时打断肌肉;肌肉被打断时归还身体并如实报告。
3. **诚实结算**:肌肉结束必须报告真实终态(位置/消耗/世界改动),并触发
   移动结算观察(diff-or-快照)。
4. **创造分支**:创造态的肌肉走飞行/瞬破路径(见创造移动重构设计,施工中),
   同名工具语义不变,实现分流。

## 3. 与既有系统的边界

- 肌肉是**工具**(大脑下单);脊髓是**反射**(自动触发)。同一段代码可以
  两用(escape_to_surface 既可被大脑调用,也可被"被困检测"反射触发),
  但入口语义分开。
- 肌肉不替代寻路:move_to 仍是通用导航;肌肉处理寻路明确不擅长的垂直/
  精确施工场景。
