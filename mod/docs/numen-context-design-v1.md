# numen 上下文机制设计 v1

**Append-Only World Cognition — 基于认知事件溯源原则的 Agent 上下文与记忆架构**

> 核心契约:
> **Observation creates immutable knowledge events.**
> **Revisits append corrections; they never rewrite prior perception.**
>
> 口号:观测即提交。历史不可覆盖,认知只能演化。

---

## 0. 本文档取代什么

本设计取代 `WorkBlockMemory` 所代表的**持续性前置重写**(Continuous Prefix Mutation)模式:动态状态块驻留系统前缀、每轮重渲染、LRU 重排、无痕覆盖旧事实。该模式的病根不在数据量,而在**首个变异点出现得太早**——一个 16 条的小字典住在缓存前缀里每轮装修一次,比尾部一万 token 的追加更昂贵。

原系统中的以下基因**保留并迁移**,不随旧模式陪葬:

- 从工具成功回执被动采集(零额外调用)
- 已加载区块的现场自愈校验
- 卸载区块凭信念保留条目 —— *distance is not evidence of absence*

---

## 1. 设计公理(约束全部实现)

1. **观测产生知识**:没有观察,不得声明事实。
2. **新知识不抹除旧知识**:新观察只能补充、修正或反驳旧观察。
3. **矛盾保留来源**:冲突是需要解释的认知事件,不是待删除的脏数据。
4. **未复查不等于不存在**:距离、区块卸载、时间流逝,都不是事实消失的证据。
5. **当前状态是推导结果**:但推导由**系统**在写入时机械完成并推送(见 §5.4),不把考古税转嫁给模型。
6. **压缩不伪造连续性**:折叠产物必须标记为重建结果,不得伪装成原始事实。
7. **稳定前缀优先**:频繁变化的信息一律置于上下文尾部。

**作用域声明**:以上公理约束**一段连续的活跃上下文**及磁盘事件日志。跨会话注入的内容可以是重建后的投影(热上下文追加,冷存储投影,事件日志永生)。

## 2. 上下文总体布局

```text
┌─ 稳定前缀(逐字节冻结,会话内绝不变更)─────────────┐
│  Agent 身份与人格(Fenn)                              │
│  不变行为规则                                          │
│  世界认知协议(事件类型定义、"同主题以最高序号/       │
│    版本为准"声明、证据强度序:observed > reported     │
│    > inferred)                                        │
│  全量工具 schema(精简 description,见 §9)            │
│  mode 目录(每个 mode 一行简介)                       │
└────────────────────────────────────────────────────────┘
┌─ 事件流(只追加,永不回改)──────────────────────────┐
│  对话轮次(user / assistant)                          │
│  tool_result(合法的第二注入通道:时间、步数、警告)  │
│  <system_notice>(纠偏与时间变更,带序号,见 §8)     │
│  REGION_SNAPSHOT / REGION_DIFF(§5)                   │
│  LANDMARK_EVENT(§4)                                  │
│  INFERENCE(§7)                                       │
│  即时感知事件(§6)                                    │
│  mode 规范文档(load_mode 的 output,见 §9)           │
└────────────────────────────────────────────────────────┘
```

**禁止事项**(违反任一条即视为回归):

- 禁止在每轮将"当前世界地图 / 当前记忆 / 当前任务状态"重新汇总塞回前缀。
- 禁止任何形式的对话中段 system role 注入;运行时指令一律以固定标签包裹,走 user turn 或 tool_result。
- 禁止在事件正文里嵌入随时间自动变化的字段(如 staleness、"距今 X 天")——这类元数据在**读取时**计算,渲染在尾部或查询回执中。

## 3. 事件通用信封

所有落入上下文与磁盘日志的事件共享统一信封:

```json
{
  "seq": 1024,
  "schemaVersion": 1,
  "type": "REGION_DIFF",
  "gameTime": 184220,
  "provenance": "observed"
}
```

- `seq`:全局单调序号。协议声明"同主题以最高 seq 为准",解决新旧事件并存时的取信问题。
- `schemaVersion`:**从第一天就存在,哪怕只有 v1**。这是整套系统最便宜的一次未雨绸缪。格式演化时读取端自动兼容(upcast:读时把旧格式翻译成新形状,旧字节不动);major 断代允许"撇了重开"(角色重生),但该字段让这成为选择而非必然。
- `provenance`:`observed | reported | inferred | system`。**分类值,不用假小数**——不生产没有下游消费者的精确性。
- 冲突事件标注 `status: requires_verification`,保留双方来源与时间,不选边覆盖。

## 4. 第一层:地标册(Landmark Memory)

回答:**重要设施在哪里、有什么用途。**

`WorkBlockMemory` 拆分为两个对象:

```java
LandmarkStore         // 磁盘中的规范状态(唯一真相)
LandmarkEventEmitter  // 向上下文追加变化事件
```

**磁盘规范态字段**:`id, label, kind, dimension, position, addedAt, lastUsedAt, status`。

**写入规则——只有语义变化才 emit**:

| 事件 | 触发 |
|---|---|
| `added` | 发现新地标(工具回执被动采集) |
| `removed` | 现场确认销毁(区块已加载且实测消失);原 `added` 事件不改 |
| `renamed` / `repurposed` | 名称或用途变更 |
| `position_corrected` | 位置修正 |

**已知地标再次使用 → 磁盘更新 `lastUsedAt` → 不调整顺序 → 不 emit → Prompt 字节零变化。**这是对旧系统第 84–85 行(remove + put 刷新新鲜度)的直接处决。

事件示例:

```xml
<landmark_event seq="1031" schemaVersion="1" type="added" id="lm_018">
  <label>基地熔炉</label>
  <dimension>minecraft:overworld</dimension>
  <position x="-17" y="64" z="23"/>
  <kind>minecraft:furnace</kind>
</landmark_event>
```

**治理**:取消 16 条硬上限与无条件 LRU 逐出。带 `label` 的地标永久保留;数量治理属于磁盘层职责(归档、按维度分表),不属于上下文层。卸载区块中的条目凭信念保留,复访实测后才产生 `removed`。

## 5. 第二层:区域观测图层(Regional Observation)

回答:**NPC 曾经看见世界是什么样。**

### 5.1 区域键

```text
(dimension, regionX, regionY, regionZ)

regionX = floorDiv(x, 16)
regionY = floorDiv(y, 64)
regionZ = floorDiv(z, 16)
```

16×64×16 分层,地下矿井与地表樱花小屋不揉成一份摘要。v1 即使只做地表,`regionY` 也必须进数据结构与索引。

### 5.2 观测流水线(被动、自动、零额外轮次)

```text
进入区域(移动系统自动触发,不消耗 tool call)
→ 低成本扫描
→ 生成规范化结构观测(纯代码:固定排序、固定模板、剔除瞬时字段)
→ 计算 semanticHash
→ 与磁盘该区域最后哈希比对
```

分派:

```text
从未观察   → append REGION_SNAPSHOT v1
hash 相同  → 零追加(复访无变化,成本为零,旧段白嫖缓存)
hash 不同  → 结构化 diff → 重要性过滤 → 按 §5.4 配对规则追加
```

需要精细定位时由模型显式调用 `scan_blocks`,结果作为 tool_result 落尾部——详查是主动工具,常规感知是被动免费。

### 5.3 规范化观测格式

哈希基于规范结构,**绝不基于自然语言文案**。给模型看的摘要由该结构渲染;渲染层措辞可改,哈希层数据不可。

```json
{
  "region": { "dimension": "minecraft:overworld", "x": -2, "y": 1, "z": 4 },
  "terrain": {
    "dominant_surface": "minecraft:grass_block",
    "biome": "minecraft:cherry_grove",
    "height_band": [63, 79]
  },
  "features": [
    { "type": "building", "bbox": [-28, 64, 66, -19, 74, 76],
      "materials": ["minecraft:cherry_planks", "minecraft:cherry_stairs"] },
    { "type": "container", "block": "minecraft:chest", "position": [-22, 65, 70] }
  ],
  "hazards": [],
  "exits": [ { "direction": "west", "kind": "path" } ]
}
```

**噪声过滤清单**(变更不触发任何追加):草花树叶随机差异、临时掉落物、普通生物路过、水流动画、农作物单阶段生长、光照变化、玩家短暂停留。否则一片麦田每长一阶段都会给上下文寄一封日报。

**重要性闸**:变更方块数 < N 且不涉显著类别 → 不追加;容器、工作站、门、红石、建筑轮廓、危险的变化 → 必追加。

### 5.4 diff 与快照的配对规则(推送式物化视图)

系统在写入时机械求和,把"当前状态"**主动推送**到尾部,模型免考古:

- **小变更**:仅追加 `REGION_DIFF`(模型从上一张快照心算一步即达)。
- **结构性变更**,或该区域自上一快照累计 diff ≥ K(默认 8),或 diff 总 token 超过上一快照的 1.5 倍:追加 `REGION_DIFF` + **紧随一张** `REGION_SNAPSHOT vN`。

成对结构的分工:**diff 回答"为什么变了",快照回答"现在是什么"。**新快照恰好落在注意力权重最高的尾部。

**版本纪律**:

- 快照带单调版本号 `vN`;前缀协议中写死"同区域以最高版本为准"。
- 旧快照不删不改,是 compaction 时第一批折叠对象。
- 快照是**可丢弃的缓存,不是真相**:`f(事件流) → snapshot` 必须是纯函数、确定性、可复现。发现某张快照算错(过滤规则 bug),作废重算,绝不修补。

### 5.5 时效性展示

`observedAt` 写入事件正文(不变);"距今多久 / 可能已过时"由读取层按当前 gameTime 现算,渲染进尾部或 recall 回执:

```text
你在约 3 个游戏日前观察过该区域。当时这里有一座樱花木屋和一个箱子。此信息可能已过时。
```

事实正文不可变;新鲜度是展示层元数据。

## 6. 第三层:即时感知(Immediate Perception)

回答:**此刻刚刚发生了什么。**

受击、拾取、饥饿、目标消失、方块改变、附近实体……短寿命事件,只存在于对话尾部,**不写入区域图层与地标册**。compaction 时默认丢弃。若某个即时事件具有长期意义,由感知策略层将其**转译**为 landmark / region / inference 事件后入册——三层不互相混用。

## 7. 推断持久化(INFERENCE 事件)

**API 事实(2026-07 对照官方文档核证,行为按模型分档)**:

- **工具调用链内**(思考 → tool_use → tool_result → 继续):thinking 块必须原样回传,带签名校验,以维持推理连贯——所有模型一致。
- **跨轮**:是否回传历史 thinking 由客户端决定。回传后,新模型(Opus 4.5+ / Sonnet 4.6+ 及之后)默认**保留**并计入上下文窗口;更早的 Opus/Sonnet 与全部 Haiku **剥离**不计费。另有 context editing 的 `clear_thinking` 策略可配置自动清理旧轮 thinking。
- **回传纪律**:回传的 thinking 块必须与原始响应**逐字节一致**(文本 + 签名),任何改动——包括看似无害的字符清洗、编码归一——都会使签名失效、请求被拒;签名与模型绑定,跨模型不可移植。保真层开启期间,禁止管线对历史 thinking 做任何文本处理。

**设计决策——两层拆开,互不绑架**:

1. **提炼层(不可省)**:重要推断显式落账为 `INFERENCE` 事件。理由:行为按模型分档,换模型即换语义,重要认知不应寄存在厂商随版本可变的通道里;思维链是草稿,发散与废案居多,全量保留是向事件流灌噪音、向账单灌 token;且 thinking 是清理机制的第一批目标,清理前必须完成提炼,否则结论随草稿一起消失。
2. **保真层(可配置)**:原始 thinking 是否跨轮保留是成本选项——预算宽、模型新则开,省钱或换模型则关;关了不丢结论,提炼层兜底。
3. **清理纪律**:`clear_thinking` 清除历史中段的 thinking 本质是一次前缀变异,会打爆其后缓存。若启用,只允许对齐 compaction 边界触发(§11),禁止随任务中途自动清理。

因此:模型的重要推断必须**显式落账**——写进正式回复,或由编排层以事件形式追加:

```xml
<inference seq="1102" schemaVersion="1" provenance="inferred">
  区域 (0,1,-1) 的箱子疑似被玩家清空(未直接目击)。
</inference>
```

`inferred` 与 `observed` 在证据强度上分级;后续的 observed 事件可以证实或反驳它——**追加,不改**。推断本就该是带来源标记的认知事件,而不是藏在思考里的暗知识。

## 8. 行为纠偏与运行时提示协议

(本设计的起点,回收归档。)

- **system prompt 不因坏习惯延长。**纠偏以 `<system_notice seq="N">` 固定标签追加在事件流尾部,借尾部 recency 权重生效。
- 同一问题重复出现 → 追加**新的** notice,语气递进;旧 notice 不修改。模型看到同一提醒出现三次、一次比一次硬,重复本身就是信号。
- 前缀协议声明:同主题以最高 seq 为准,消解新旧提醒并存的歧义。
- 时间戳变更走同一通道:尾部追加变更通知,永不改前缀。
- `tool_result` 是合法第二通道:步数、预算、警告等系统状态可附于工具回执,无需伪造额外 user turn。

## 9. Load Mode:工具规范按需加载

**schema 层全量注册,说明层按需加载。**

- API `tools` 参数从第一步声明全部工具,description 压至一句话(例:`browser_click: 点击页面元素。详细规范需先 load browser mode`)。schema 一次性入缓存前缀,永不变动——中途新增 tool schema 与改前缀时间戳同罪。
- `load_mode(name)` 的 output 是该 mode 的使用规范长文(工作流约定、注意事项),作为 tool_result 落入事件流。
- **mode 文档必须逐字节确定**:版本化静态文件,不动态拼接时间等易变内容。目的:可 diff、可复现。
- 切换 mode:追加一句"X mode 规范已由 Y 覆盖,以下文为准"——声明覆盖,不删除。
- 失活 mode 文档在 compaction 时折叠。

## 10. 磁盘事件日志与 recall_region

架构血缘:Event Sourcing + CQRS。磁盘事件日志 = 写模型(唯一真相);上下文 = 主动推送的热投影;`recall_region` = 一次按需的物化视图查询。

```text
上下文:最近与关键认知(推送快照 + 近期 diff)
磁盘:  完整事件历史(append-only)
工具:  recall_region(region_id)
        → 磁盘重放(最新快照 + 其后 diff)重建该区域当前认知
        → 回执落尾部
```

**滞后即认识论,不是 bug**:上下文认知落后于世界是观测式记忆的定义(人类亦然)。Fenn 到场发现不符时,那一刻的新观测**本身就是修正事件**,系统天然自洽,无需版本协商机制。

**继承边界**:numen 单写者,ES/CQRS 为分布式多写者设计的乐观并发、冲突合并、saga 补偿整层跳过。且本系统的读模型喂给语言模型而非代码——投影可以激进压缩为几句自然语言,这是 LLM 时代独有的红利。

## 11. Compaction:唯一合法的重写边界

平时 append-only;compaction 时缓存反正全毁,是集中重写的唯一合法时刻。

**触发**(任一):总 token 阈值 / 步数阈值 / 旧快照与已解决 notice 堆积量。

**动作**:

1. 各区域仅保留最高版本快照及其后 diff;更早的段折叠归档(磁盘日志完整保留)。
2. 移除失活 mode 文档。
3. 已解决的 `system_notice` 折叠为一句结论。
4. 即时感知事件丢弃。
5. **折叠产物显式标记为重建结果**(公理六),保留时间、来源、矛盾与不确定性,不伪装成原始事实。

compaction 后:新前缀 = 原冻结前缀 + 折叠段,追加重新开始。

## 12. 遗忘协议(双盲记忆)

- **双盲**:user 与 agent 都不能指挥记忆生成器;生成器依本协议规矩生成,不受任何一方干预。
- 玩家要求遗忘 → 追加一条约定事件,内容不删:

```xml
<memory_covenant seq="1210" schemaVersion="1" provenance="system">
  玩家要求不再提及:{摘要引用}。守约:后续对话绝不主动提起。
</memory_covenant>
```

- **创伤与失败不可删除**——现实中你也无法要求一个人忘掉某件事;能要求的只是他守口如瓶。Fenn"记得但守约不提",遗忘请求成为一条新记忆,而非一次篡改。
- **疆界备忘**:本协议成立的前提是 Fenn 的记忆无对外导出接口,按人脑伦理办。若未来任何记忆内容涉及可导出的真实个人数据,该部分适用"删除留痕"规则(`MEMORY_REDACTED`:页在,字空,注明依谁的要求)——同一骨架,内容清空与否取决于记忆的主人是谁。

## 13. 验收条件

功能验收:

```text
 1. 同一熔炉连续使用 20 次 → 系统前缀字节完全一致
 2. 首次进入区域 A → 只追加一个 snapshot
 3. 离开 A 进入 B → A 的历史段不得被修改
 4. 回到 A,世界未变 → 不追加任何区域事件
 5. 修改 A 的显著建筑后复访 → 追加一个结构化 diff
 6. A 所在区块未加载 → 不得将旧地标判定为消失
 7. 地标现场确认被毁 → 追加 removed,不改最初 added
 8. 同一观测重复扫描 → 规范化 hash 稳定
 9. 麦苗生长、动物路过等噪声 → 不触发区域 diff
10. 小变更连续发生 → 仅 diff,无快照堆积
11. 结构性变更 → diff + snapshot 成对追加,一次完成
12. 同区域多快照并存 → 模型问答以最高版本为准(行为测试)
13. 上一轮推断落账后 → 下一轮仍可被引用(INFERENCE 生效)
14. 遗忘请求后 → 内容仍在磁盘,行为层不再主动提及
15. 累计超过阈值 → compaction 正确折叠,重建认知与磁盘重放一致
```

缓存回归(比肉眼看日志可靠):

```text
16. 记录连续 50 轮请求的 prefixHash:
    世界无结构性新知识时,prefixHash 始终不变
```

## 14. 实施顺序

```text
第一棒  事件信封(seq / schemaVersion / provenance)
        + 地标册改造(拆 WorkBlockMemory → Store + Emitter)
第二棒  区域观测流水线(键、规范化、semanticHash、噪声闸、配对规则)
第三棒  磁盘事件日志 + recall_region
第四棒  system_notice 纠偏协议 + load_mode
第五棒  compaction
```

验收条件 1、7 在第一棒结束即可跑;16(prefixHash 回归)从第一棒起持续挂在 CI 上——缓存漏水要在暗处漏第一滴时就被看见。
